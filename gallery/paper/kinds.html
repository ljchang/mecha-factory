Every field kind

One of each. This page is a rendering gallery: the browser validates natively, and submitting goes nowhere.

One line. max_length is required on every text field — these forms sit on an unauthenticated endpoint, and an uncapped field is an unbounded write.

Two letters, a hyphen, four digits — NH-0301. The pattern rides on the input and the browser enforces it; the server enforces the cap and the type, never the regex.

Many lines, same cap rule. Free text, which is what the front door quarantines: a privileged run sees the extraction of this, never the prose.

Capped at 254 by default, the practical maximum for an address. [verification] names this field, which is why it has to be required.

Data to show, never a thing to fetch. Nothing in this crate resolves one, and nothing downstream should — a form field is not a reason to make an outbound request to an address a stranger chose.

YYYY-MM-DD, inclusive bounds. Literal dates rather than offsets: an offset would have to be resolved against a clock, and the browser's clock is not the server's.

Inclusive bounds, enforced at both ends.

One of ours. Nothing a stranger types can change which value this carries, which is what keeps the kind of a request out of their hands.

Several of ours, up to max_choices. Renders as checkboxes rather than a multiple <select>, which nobody has ever operated correctly on a phone.

A single boolean. Distinct from an acknowledgment, which is always required and carries something to read first.

On the public form this renders as a note rather than an input: uploads happen after the address is verified, so the upload page is the one place a file input exists.
